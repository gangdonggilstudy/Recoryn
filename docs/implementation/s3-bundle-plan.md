## 1. 기준과 집계

- 제품과 기존 시험의 판단 기준은 HEAD b92552059ef3b19b038e97cba3e3c44996fc5ee1이다. 아래 제품·시험의 파일:줄은 모두 이 commit 기준이다. 작업 트리의 G-P08·G-P11b 변경을 이미 통합된 구현으로 계산하지 않았다.
- 입력은 docs/implementation/v1-gap-plan.md:78의 이후 묶음, docs/collaboration/assignments.md:39의 G15c 행, 각 원 검토 문서다. 제품과 시험은 git show로 대조했고, 전체 소스·시험 검색에는 Git archive를 메모리에서 읽었다. 저장소나 TEMP에 새 분석 사본을 쓰지 않았다.
- 이 분석에서 시험·성능 측정·변이를 새로 실행하지 않았다. 시험의 존재와 단언 내용을 직접 읽은 사실, 과거 검토 문서의 실행·측정 결과, 승인된 후속 계약을 구분한다. 예를 들어 G15c의 0.5~0.6초는 docs/reviews/g15-seal-mutex-review.md:328의 관측 인용이다.
- 상위 항목은 **16개**다: GF-15~18 4개, G01BR-11~17 7개, G02B-01 1개, G05R-07 1개, G-P05b 관찰 2개, G15c 1개. GF-15·GF-18·G01BR-16·G15c는 세부 요구를 분리해 인계한다. 하위 요구를 별도 상위 항목으로 중복 계수하지 않는다.

## 3. GF-15와 GF-18의 중복 제거·인계 경계

### GF-15

1. **이미 해결된 부분**: G-P03의 전사/요약 선택 version, summary_requests.settings_key, 게시 transaction의 CAS는 다시 만들지 않는다. G-P07의 현재 실행 generation·첫 수락/ready 표시도 그대로 보존한다.
2. **P08 미디어 메타데이터**: G1A-20의 정확한 제어 cutoff/fragment·ACK 사실, G1A-31의 요청/실제 포맷·layout/valid bits·mask·epoch 정체성, G1A-54의 descriptor 시간·frame/flags 요약, G1A-80의 트랙 역할/안전 표시명 등이다. G-P08의 건강 run/track/event를 정본으로 삼는 필드와 descriptor에 필요한 필드를 구분하고, 같은 사실의 독립 정본을 둘 만들지 않는다. clock domain 전체는 별도 GF-06이며 이 S3 단위로 몰래 포함하지 않는다.
3. **P09 content/Job 메타데이터**: G1A-81~84의 언어·confidence availability·source ref·model/config·actor/cause·진행량을 다룬다. 비용 정책·동의 범위·정책 version·사용자 책임 확인만 바뀐 값을 결과 config_key에 다시 넣지 않는다. G-P06의 비용 감사 기록을 content event 정리 대상으로 섞지 않는다.
4. **G1A-89 잔여 표시/포인터**: CAS와 별개인 machine latest/사용자 active 분리 및 현재 설정 기준 OUTDATED다. G-P12가 맡은 후보 선택 UI·CAS와 먼저 대조해 API/필드를 한 번만 추가한다. G12에서 닫힌 하위 요구는 P09의 남은 분모에서 뺀다. 새 immutable revision 필드와 additive 표는 G-P09a의 버전 목록에 등록한다.

### GF-18

- G04 K5/K6/K8의 실제 kill→복구→확정→export 체인과 고정 전사 SRT 재생성은 존재한다. 원 보고서의 “시험 없음”을 현재 사실로 복사하지 않는다.
- 기본 root는 LOCALAPPDATA 있음/없음 분기를 외부 파일 변경 없이 환경 fixture로 검증한다. CLI 오류는 일반 오류·삭제·확정/복구 분기를 구분하고 canary 비밀·원문·경로·repr가 출력에 없는지 확인한다. 이는 기존 일부 닫힌 오류 코드 시험을 대체하지 않는다.
- 오디오 반복 export는 같은 고정 입력을 서로 다른 새 대상에 내보내 WAV 내용/frame·매핑의 의미 동일성을 확인한다. UUID 출력 경로를 그대로 비교하는 oracle는 피한다. G-P10의 향후 분할·완료 marker도 같은 oracle를 승계한다.
- golden fixture는 구현 serializer를 다시 호출해 기대값을 만들지 않는다. v1 bytes와 해시·형식 읽기 호환을 고정하고, P08의 v2가 승인되면 별도 고정 fixture를 추가한다. G-P17의 저장 완료/내구성 의미와 bytes 형식의 동일성은 다른 요구다.

## 6. C00 결정 요청과 미검증 범위

1. 상위16개·신규10개 분할, GF-17의 S2 재분류, G01BR-11의 기능 S2 유지/판정 정정과의 분리를 확인해 주기 바란다.
2. P01의 공통 실패 처리에도 장치 alert 우선·별도 결과 표시를 적용하고, 선택 slot 실패를 안전한 read model로 처리하는 방향을 승인할지 결정한다.
3. P02를 G08과 G17a 사이에 먼저 닫을지 결정한다. 실패 cache는 fail closed·settle·명시 재조회·capture 독립성까지 하나의 계약으로 검토해야 한다.
4. P03의 기존 파일 기본 거부/명시 원자 교체 중 정책, P04의 허가 후 probe 범위, P05의 credential resolver 수명, P08/P09의 정확한 형식·필드 범위를 각각 계약 단계에서 승인한다. 이 분석이 제품 API 변경 승인은 아니다.
5. 이미 존재하는 G03/G04/G05b/G07 시험과 G12/G13에서 닫힐 시험은 재사용한다. 새로운 단위별 feasible 분모·독립 oracle·변이·시간 예산은 착수 계약에서 제시한다. 이 문서에는 실행하지 않은 새 PASS 수나 시험 분모를 만들지 않았다.

실제 장치의 큰 패킷, 실제 공급업체 probe, 실제 vault, Narrator, 전원 장애·실제 디스크 성능은 이번 읽기 분석으로 검증하지 않았다. 과거 검토의 실행 숫자는 원문 인용이며 새 측정으로 취급하지 않는다. 최종 등급·소유자·배정 순서·승인은 C00 몫이다.
