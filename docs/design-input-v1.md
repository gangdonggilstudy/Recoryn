# Recoryn Architecture & Expert Review v1.0

상태: 사용자 제공 제안 설계. 구현 및 Windows 검증 전. 기준: VoiceLocal v0.1.0. 동일하게 두 번 전달된 본문을 한 번으로 정리한 요구사항이다. 현재 저장소에는 VoiceLocal 소스가 제공되지 않았다.

## 제품 원칙

| ID | 요구사항 |
| --- | --- |
| R01 | STT 또는 LLM 실패와 관계없이 녹음을 계속한다. |
| R02 | 로컬 전용이 기본이다. 외부 전송은 제공업체 및 데이터 종류별 명시적 동의가 필요하다. 모델 다운로드도 명시적 사용자 동작이다. |
| R03 | 마이크와 시스템 트랙을 분리하고 원본 미디어를 불변으로 보존한다. 모든 변환은 파생 산출물이다. |
| R04 | 작업은 재개, 취소, 관측이 가능해야 하고 부분 결과를 보존한다. 녹음 재개와 중단 구간 복원은 구분한다. |
| R05 | BYOK 비밀은 Windows Credential Manager에 보관하며 로그나 프로젝트 내보내기에 포함하지 않는다. |
| R06 | 모델 및 제공업체 어댑터는 선택적이며 기능 지원 여부를 검사한다. |

## 전문가 관점

수석 아키텍트는 경계, 호환성, 마이그레이션과 성능 예산을 검토한다. Windows 오디오 전문가는 WASAPI 루프백, 캡처 시계, 장치 변경, 드리프트와 에코를 검토한다. ML 전문가는 스트리밍 STT, VAD, 화자 구분, 로컬 및 클라우드 요약과 평가를 담당한다. 보안 및 라이선스 전문가는 데이터 흐름, 비밀, 동의, SBOM과 의존성을 검토한다. UX 전문가는 접근성, 명확한 녹음 상태, 안전한 기본값과 복구를 검토한다. QA 및 릴리스 전문가는 단위·통합·하드웨어 시험, CI와 재현 가능한 빌드를 검토한다. 이 역할은 검토 기준이며 전문 자격이나 실제 하드웨어 검증을 뜻하지 않는다.

## 모듈 제안

`src/recoryn/` 아래에 `app`, `domain`, `capture`, `audio`, `transcription`, `summarization`, `jobs`, `storage`, `security`, `ui`, `diagnostics`를 둔다. UI는 PySide6, 메타데이터는 SQLite, 미디어와 전사·요약은 파일로 관리한다. 정확한 오디오 백엔드는 하드웨어 시험 후 결정한다.

## 캡처와 복구

장치 기본 샘플레이트 및 채널 → 타임스탬프 PCM 블록 → 제한된 쓰기 큐 → 청크 파일과 manifest → 선택적 파생 리샘플링 → VAD → 스트리밍 전사 초안으로 흐른다. 종료 후 청크 확정, 무결성 확인, 시간과 드리프트 기반 정렬, 파생 믹스, 전체 전사, 정정 전사 원자적 게시, 선택적 요약을 수행한다.

녹음 스레드는 모델 추론이나 무거운 디스크 변환을 호출하지 않는다. 큐 포화 시 심각한 상태와 유실 프레임 수를 표시하며 조용히 버리지 않는다. 장치 분리, 디스크 부족, 절전 및 복귀, 비정상 종료를 다룬다. 녹음 중 WAV의 44바이트 고정 헤더를 건너뛰는 snapshot 방식 대신 버퍼나 확정 청크를 사용한다. 무손실 녹음을 시험 없이 주장하지 않는다.

## 상태와 제공업체

사용자 초안 흐름은 `CREATED → RECORDING → FINALIZING → TRANSCRIBING → READY → SUMMARIZING → COMPLETE`다. `FAILED`, `CANCELLED`는 작업별 복구 가능한 종료 상태다. 녹음 세션과 작업의 상태 분리가 필요하며 전이는 영속화한다. 내보내기는 반복 실행 가능해야 한다.

STT 계약은 기능, 언어, 입력 제한, 개인정보 범위, 예상 비용과 `transcribe()`를 포함한다. 요약 계약은 기능, 컨텍스트 크기, 예상 비용과 `summarize()`를 포함한다. STT와 요약 제공업체는 독립 선택이다. 로컬 Faster-Whisper를 기본으로 하고 로컬 Ollama 요약은 선택한다. 클라우드 전사와 요약의 동의는 분리한다.

긴 문서는 겹치는 문맥, 구조화한 중간 요약과 최종 통합으로 처리하고 세그먼트와 시간 참조를 보존한다. 근거 없는 주장과 불확실한 부분은 표시한다. GPU 메모리를 탐지하고 여유분을 확보하며 필요시 무거운 추론을 직렬화한다. CPU 전환은 사용자가 허용하는 경우에만 한다.

## UX와 보안

메인 화면은 장치 선택, 트랙별 미터, REC 표시, 경과 시간, 일시정지·정지, 임시 전사와 경고를 제공한다. 세션 후 원본·정정 전사, 시간 검색·재생 이동, 내보내기, 회의·강의·결정·할 일 요약, 출처 연결, 감사 이력이 있는 편집을 제공한다.

외부 호출은 데이터 종류와 수신자를 보여준다. 삭제·보존 정책, 로그 가림, 녹음 동의 안내, 의존성·라이선스 목록과 재배포 전 모델 가중치 라이선스 검토가 필요하다. 제공업체 예시는 Ollama, OpenAI, Anthropic, Gemini 및 호환 API이며 실제 기능은 어댑터별로 검증한다.

## 검증과 우선순위

단위 시험: PCM, 시간 계산, 정렬, SRT, 상태 전이, 복구. 통합 시험: 합성 다중 시계, 느린 STT, 모델 예외, API timeout, 네트워크 차단, 디스크 부족. Windows 하드웨어 시험: 여러 입출력·Bluetooth·44.1/48 kHz·장치 재연결·절전·장시간 세션. 벤치마크: 유실, 드리프트, 허가된 음성의 WER/CER, 요약 사실성, GPU 메모리, 초기 실행과 내보내기 무결성. 릴리스: 깨끗한 Windows VM, EXE smoke test, 코드 서명 결정, 라이선스와 SBOM 검토.

| 우선순위 | 범위 |
| --- | --- |
| P0 | 장치 기본 포맷 캡처, 타임스탬프, 청크 저장, 복구, 오디오·AI 작업 분리, manifest, Windows 하드웨어 검증 |
| P1 | VAD 스트리밍, 정정 전사, 시간 검색 UI, 로컬 Ollama, 비밀 저장소, 제공업체 권한 UI |
| P2 | 클라우드 BYOK, 비용 상한, 분할 요약, 화자 구분, 설치 프로그램과 CI |
| P3 | 다국어 UX, 플러그인, 고급 편집과 내보내기 템플릿 |

초기 개발 단계는 v0.2 안정화 → v0.3 로컬 AI → v0.4 클라우드 → v0.5 사용성 → v1.0 공개 배포다. 실제 릴리스 게이트와 P0~P3 매핑은 통합 설계에서 정한다.

## 열린 결정

오디오 백엔드 선택은 하드웨어 시험 후 결정한다. 번들 바이너리·모델·UI 의존성의 라이선스를 검토한다. 클라우드 자동 fallback 기본 차단과 화자 구분의 선택 다운로드를 권고하되 통합 설계의 결정 기록에서 상태를 명시한다.
