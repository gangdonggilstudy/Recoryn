# Recoryn 시험 경우의 수 설계

상태: 2026-11-15 사용자 요청으로 채택하는 실행 규칙. 시험 개수와 line/branch coverage는 실행 관측 지표이며 정당성 증명과 구분한다. 실제 결과는 배정별 case matrix·독립 리뷰·push 단위 증거에 기록한다.

## 입력 공간과 분모

각 변경은 요구사항/위험과 독립 oracle를 정한 뒤 인자별 동치류와 경계를 나눈다. 유한 대표 집합 D1…Dn의 직적 Ω에서 구성·실행이 가능한 조합 F를 정의한다. 무제약 개수는 |Ω|=∏|Di|이고 제약 후 분모는 |F|다. 생성기와 별개로 분모를 산출해 누락·중복을 대조한다. 제품이 거부해야 하는 입력·전이를 F에서 제거하지 않는다. 제외는 fixture 구성 자체의 불가능성 등 구체 근거와 독립 검토를 요구한다.

| 차원 | 필수 분할 예시 | 확인할 결과 |
| --- | --- | --- |
| 숫자·크기 | 최솟값−1/최솟값/최솟값+1, 최댓값−1/최댓값/최댓값+1, 0/빈값, overflow | 수락·거부와 원본/상태 불변, 정확한 단위·반올림 |
| 타입·부동소수점 | 정수와 bool 구분, 문자열/None, NaN/±Inf, 정밀도 한계 | 안전한 오류, 음수·비유한 시각·비용의 게시 차단 |
| 상태·버전 | 모든 source×target, 현재/과거/미래 버전, 정상/오래된 fence | 합법 전이와 거부, terminal 불변·늦은 게시 차단 |
| identity·권한 | provider/endpoint/data/session/세대/동의/owner 일치·불일치 | 하나라도 빠진 권한은 연결·본문 전달 전 차단 |
| 산출물·부분 성공 | empty/silent/partial/complete, edited·선택·후보 | 빈 정상 결과와 실패 구별, provenance·CAS 보존 |

예를 들어 6개 상태와 3개 기대 버전 구간이면 syntactic 전이 행은 6×6×3=108이다. 이는 설계 예시이며 해당 108개가 현재 시험됐다는 결과가 아니다. 실제 수락/거부 oracle는 제품 계약에서 독립 표로 정의하고 구현의 전이표를 그대로 import해 기대값으로 쓰지 않는다.

## 조합과 결정

작고 고위험인 유한 결정은 전수 열거를 우선한다. 이진 인자 n개의 독립 결정 cube는 2^n이다. 동의·삭제·fence·비용·원본 무결성은 단일 인자 부정 case뿐 아니라 다중 실패와 진단 우선순위도 확인한다. 독립 원인 변화가 결과를 바꾸는 case를 포함하되 이를 규제 인증이나 전체 코드의 MC/DC 달성이라고 부르지 않는다.

큰 공간은 위험을 기준으로 t-wise를 선택할 수 있다. 분모는 F에서 가능한 인자 t개 조합의 값 tuple 집합이다. 서로 다른 인자 부분집합도 구분해 센다. 관측한 feasible tuple 수/전체 feasible tuple 수를 기록하고 빠진 tuple을 검출한다. pairwise를 전체 조합 coverage나 3개 이상 상호작용의 증명으로 쓰지 않는다. 고위험 고차 상호작용은 별도 필수 행으로 남긴다.

동치류 하나의 대표값을 통과한 사실은 그 구간 전체의 증명이 아니다. 구간 내부의 속성 시험, 경계와 독립 수학 oracle를 결합해 근거를 보강한다.

## 상태열과 경쟁 순서

상태 모델은 이벤트 alphabet, 합법/거부 전이, 관측 상태와 불변식을 먼저 적는다. 깊이 L까지의 명령열이나 작은 상태 공간을 제한 전수 탐색하고, 도달 상태·전이·전이 쌍·terminal 재진입·중복 명령의 누락을 확인한다. 더 긴 이력은 Hypothesis stateful 등 생성 시험으로 보강한다. bound L 밖은 미검증으로 명시한다.

경쟁은 happens-before 관계를 DAG로 적고 그 관계를 보존하는 linear extension을 센다. 독립 이벤트 3개는 3!=6순서, 각 내부 순서를 지키는 길이 2인 두 chain은 C(4,2)=6, 세 chain은 6!/(2!³)=90이다. 실제 이벤트 단위와 제약을 명시하지 않고 이 숫자를 시험 완료로 기록하지 않는다. barrier/Event와 fake clock으로 순서를 강제하며 scheduler의 우연한 선택이나 긴 sleep을 전수 실행으로 삼지 않는다. 순서 축약은 결과·관측·read/write 독립성의 근거를 남긴다.

취소↔게시, 삭제↔reader ACK, 철회↔첫/후속 write, owner 종료↔늦은 callback은 양쪽 선형화 결과와 이미 handoff된 작업을 구분한다. timeout 직전/동일/직후와 ACK 중 도착도 포함한다. 테스트용 상태 파일도 완성 후 원자 게시해 fixture의 부분 읽기를 제품 장애와 구분한다.

## 필요한 시험의 적용

| 방법 | 적용 근거 | oracle 및 관측 |
| --- | --- | --- |
| 유닛·매개변수화 | 유한 전이/결정/경계/타입 | 손계산 표·허용/거부·상태 불변, 유일 case ID |
| 속성·metamorphic | 수치 범위·분할·정렬·재시작/멱등 | 길이·frame/byte 보존·partition/reorder 관계와 명시 오차 |
| 상태 모델 | 여러 명령의 이력·retry/fence/취소 | 구현과 독립한 작은 모델·도달/거부 전이·최소 실패 trace |
| 동시성 | 선형화·철회/삭제/종료·UI | 결정적 barrier·양순서·새 write/늦은 게시 관측 |
| 통합·장애 주입 | 파일/SQLite/프로세스 경계 | 실제 임시 저장소·소유 subprocess·ENOSPC/short write/crash 후 독립 checksum |
| mutation | 중요한 비교/검사 삭제가 누락될 위험 | 정상본 PASS·격리 mutant의 목표 assertion FAIL, 코드 원본 불변 |

기존 시험으로 충족한 행은 기존 node ID와 근거를 연결한다. 같은 계산식을 복사하는 새 시험·성공만 확인하는 smoke의 중복으로 시험 개수를 늘리지 않는다. 필요한 계층을 생략해서도 안 된다. 모든 계층을 무조건 모든 함수에 적용하는 규칙은 아니다.

mutation은 임시 소스 사본에서 비교 반전·검사 제거 등 명명한 결함을 한 번에 하나씩 적용한다. 실제 workspace·인덱스·사용자 데이터는 변경하지 않는다. import/수집 실패·권한 오류·timeout만 발생한 경우에는 목표 결함을 잡았다고 세지 않는다. 정상/변이 실행 명령, 소스 hash와 실패 node를 기록하고 survived/invalid/equivalent를 독립 검토한다. 일부 mutant의 통과율을 전체 프로젝트 mutation coverage라고 부르지 않는다.

## 제출과 수락

배정별 문서는 다음을 포함한다: 요구사항/위험, 인자와 동치류/경계, 제약과 제외 사유, 분모 산식·유일 case ID, 기존 시험 대응, 추가 시험 node와 계층, 독립 oracle, 실제 관측 수/누락·중복·불가 case, seed/bound/오차, mutation 결과와 한계. 정의/예시/생성 개수/실제 실행을 구별한다. 최소 반례는 비민감 fixture로 재현 가능하게 보존한다.

작성자 외 검토자는 분모와 제약의 누락·과도한 제외, oracle가 구현에 종속됐는지, mutant가 실제 assertion으로 검출됐는지 확인한다. line/branch의 기존 기준은 유지하며 선언한 필수 case의 누락과 고위험 미해결은 수치가 높아도 수락하지 않는다. 최종 증거는 검증한 파일/commit과 [push 단위](../collaboration/push-units.md)에 연결한다.
