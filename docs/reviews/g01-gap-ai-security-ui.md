- 정본은 배정표 맨 위 **2026-11-22 G**다. `architecture-v1.md`의 AI 제공업체와 자원 관리, 전송 동의와 비용, 비밀과 데이터 수명, UX와 관측 및 관련 상태·revision 계약을 요구 단위로 분할했다. `validation-plan.md`의 C01/C02/I01~I07/M01/M02/E01/E02/S01~S04/W05/REL01/REL02, 제품 계약 B10/B13/B14, provider-matrix와 diarization을 연결했다.
- 아래 경로의 행 번호는 현재 파일을 직접 읽고 검색한 결과다. 표의 구현 경로는 저장소 상대 경로다. `DONE_VERIFIED`는 **그 행에 한정한 코드와 직접 관련 시험 assertion이 존재함**을 뜻한다. 실모델·실서비스·전체 설계 완료를 뜻하지 않는다. 직접 실행 여부는 아래 실행 집합으로 구분한다. 실행 집합 밖 시험은 존재·내용 확인 근거이며 이번 실행 PASS로 세지 않는다.
- `PARTIAL`은 요구의 일부 구현, `MISSING`은 해당 계약 또는 사용자 경로 부재다. 재현 근거는 코드 읽기로 재현하는 절차이며 새 반례 시험을 작성·실행한 결과로 주장하지 않는다. `EXTERNAL_GATE`는 장비·모델·계정·관측 환경·사람 평가 등이 필요한 별도 검증이다. `DEFERRED`는 설계가 명시한 v1.0 이후 범위다. 위험은 요구가 깨질 때의 영향이며, 실제 사고가 발생했다는 뜻이 아니다.

## 주요 gap의 재현과 후속 단위 경계

다음은 새 시험 결과가 아닌 **현재 코드에서 따라갈 수 있는 재현 절차**다. 모든 재현은 후속 구현 배정에서 fake/임시 SQLite·offscreen으로 먼저 반례를 고정해야 한다. 실제 장치·모델·원격 서비스가 필요하지 않다.

1. **F-SEC01 / G01B-040 / S0**: ConsentStore.grant(provider, endpoint, data_type) 한 건 뒤 session A/B를 각각 bind하고 두 Gateway.for_session으로 같은 provider/endpoint/data 요청을 계획한다. grant에는 A 식별자나 policy version을 넣을 인자가 없으므로 session 범위 허용 여부를 검사할 수 없다. UI에도 범위 선택이 없다. 목적은 기존 강한 철회 경계를 보존하면서 grant 자체의 허용 대상·기능·정책을 좁히는 것이다. 공개 schema/API 변경이므로 C00 재배정과 G01-A 조정이 선행이다.
2. **F-SUM02 / G01B-024 / S1**: T1/S1에서 작업의 expected ID를 캡처한 뒤 select_transcript를 T2→T1(또는 select_summary S2→S1)로 이동한다. `_select`는 version을 증가시키나 게시자는 version을 전달하지 않는다. `_create_summary`의 ID 조건은 다시 같아진다. 별도로 T1 고정 상태에서 UI 템플릿/모델 설정만 바꾸면 summary.stale는 여전히 transcript ID만 검사한다. 포인터 비교 시험이 있는 사실을 selection version 요구 충족으로 확대하지 않는다.
3. **F-COST01 / G01B-046 / S1**: cloud 설정의 per_request를 양수 작은 값으로 두고 큰 입력의 execution_context를 만든다. reserve callback은 body_size에 비례한 과금 한도 계산 없이 그 cap을 예약한다. `CostLedger` 테이블에는 통화·기간·가격 기준시각 열도 없다. strict 모드에 필요한 것은 사용자 희망 cap뿐 아니라 모델/요청별 검증된 upper bound와 미상일 때의 차단이다. 보수적 UNKNOWN 유지 구현은 그대로 보존한다.
4. **F-RES02 / G01B-031 / S1**: MainWindow.device_policy=GPU_ONLY로 선택하고 fake의 유효 local Ollama proof와 summary config를 공급한다. `_transcribe`와 달리 `summarize`는 device_policy를 읽지 않는다. 요청 body에는 서버의 strict GPU 실행 보장을 강제/검증하는 값이 없다. 따라서 지원하지 않으면 admission에서 차단하는 계약과 표시를 추가해야 한다.
5. **F-MOD02 / G01B-032 / S1**: ModelManager 설치 이력 없는 로컬 폴더에 필수 세 파일을 둔 fake model factory 경로를 따라간다. adapter는 파일 존재·경로를 검사하고 local_files_only로 로드하며 신뢰 manifest/license 승인 증거를 받지 않는다. 수동 모델 사용 자체를 없애기보다 로컬 import 확인·고정 digest 증거를 설치 경로와 같은 수준으로 연결할 수 있다.
6. **F-LIFE02 / G01B-067 / S1**: 동일 창에서 DELETE_PENDING을 만든 뒤 창을 재생성한다. `_pending_deletions`는 빈 dict이며 list_sessions는 의도대로 삭제 대상을 숨긴다. pending 조회를 복원할 코드가 없어 재시도 버튼이 비활성이다. 현재 동일 창 재시도 시험과 별개인 재시작 시험이 필요하다.
7. **F-SUM01 / G01B-021/022 / S1**: refs 없는 unsupported claim, unresolved ref claim, user_assertion ref claim을 fake 요약 결과로 공급하고 실제 ContentPanel._show_summary까지 비교한다. provider basis·저장 basis·표시 status가 각 경계에서 어떤 값을 유지하는지 확인해야 한다. 현재 UI는 status만 보여주며 decisions/tasks도 같은 목록이다. 구조 검증과 의미 검토/확정 영역을 분리한다.
8. **F-A11Y01 / G01B-068 / S1**: 검색 결과의 시작 시간 셀에 키보드로 이동해 Enter/Space를 누르는 경로를 Qt signal 연결과 대조한다. 현재 seek는 cellDoubleClicked에만 연결된다. 녹음 단축키 등록 확인을 전사 탐색·거부/철회 전체 E02 시험으로 계산하지 않는다.
