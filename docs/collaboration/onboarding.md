# Recoryn 새 세션 온보딩

## 읽기 순서

1. 루트 [AGENTS.md](../../AGENTS.md): 권한, 현재 단계와 금지 사항.
2. [설계 입력](../design-input-v1.md): 사용자 요구사항과 미결정 항목.
3. [통합 설계](../architecture-v1.md): 계약과 채택 결정. 초기 작성 중에는 존재 여부를 확인하고 미작성 부분은 추정하지 않는다.
4. [협업 규칙](workflow.md), [작업 배정표](assignments.md): 책임과 쓰기 범위.
5. 배정에 관련된 `docs/reviews/`의 전문가 검토와 [검증 계획](../validation-plan.md).
6. [품질 및 교차 검증 체계](../quality-system.md): 시험 계층, 독립 검토, 증거와 통과 기준.
7. 구현 배정 시 [제품 구현 계약](../implementation/product-contracts.md)과 [현재 구현 증거](../implementation/product-results.md), 기존 [코어 결과](../implementation/p0-results.md)를 읽는다. 설계 문서의 당시 NOT_RUN 상태와 현재 증분의 실제 증거를 구별한다.
8. [경우의 수 설계](../testing/case-space.md)와 [푸시 단위 규칙](push-units.md)을 읽는다. 배정의 입력 인자·제약·시험 분모·oracle·선택 계층과 push ID/소유 파일/필수 게이트를 ONBOARDING_READY에 포함한다. 아직 조사 중인 값은 추정 통과로 채우지 않는다.

## 시작 확인

현재 cwd가 배정한 Recoryn 경로인지 확인하고 `git status --short`, 현재 브랜치, 관련 파일을 읽는다. Herdr를 사용한다면 `HERDR_ENV=1`, `herdr --skill`, 도움말과 현재 pane 목록을 확인한다. 도구의 권한을 넓히거나 승인 UI를 대신 수락하지 않는다.

오케스트레이터에게 다음을 보고한다.

```text
ONBOARDING_READY
배정 ID / 전문가 역할:
읽은 규칙과 설계 문서:
수정 허용 파일:
이번 작업의 수락 기준:
이해한 핵심 규칙: 원본 보존 / AI와 녹음 분리 / 외부 전송 기본 차단 /
  작업자 commit·push 금지 / 파일 소유권 준수
현재 변경과 충돌 여부:
확인이 필요한 사항:
```

누락된 규칙이나 배정 충돌이 있으면 읽기 전용으로 대기한다. 문서를 읽었다는 보고만으로 구현 범위를 넓히지 않는다. 지정된 배정 ID와 소유 파일, 수락 기준을 오케스트레이터에게 받은 뒤 해당 범위에서 작업한다.

## 신규 세션 지시 템플릿

```text
Recoryn 작업 세션으로 합류하세요. 먼저 루트 AGENTS.md와
docs/collaboration/onboarding.md의 순서대로 필독 문서를 읽으세요.
현재 단계는 [설계/구현/검증]입니다.
배정 ID: [...]
전문가 역할: [...]
쓰기 허용 파일: [...]
목표와 수락 기준: [...]
제외 범위 및 의존성: [...]
ONBOARDING_READY를 보고하고, 이 배정 범위에서 작업하세요.
공용 파일과 Git 인덱스를 수정하지 말고 commit/push하지 마세요.
완료 시 변경 파일, 결정, 검증, 미해결 사항을 보고하세요.
추가 에이전트나 Herdr pane을 임의 생성하지 마세요.
```

## 교대와 재개

교대 시 진행 중인 배정, 소유 파일, 저장한 결과, 검증한 내용, 미해결 사항과 다음 행동을 보고한다. 후임은 현 파일을 다시 읽고 배정표 갱신을 받은 뒤 이어간다. 이전 채팅 기억이나 과거 pane ID에만 의존하지 않는다. 기존 세션의 종료나 재사용은 오케스트레이터가 명시적으로 결정한다.
